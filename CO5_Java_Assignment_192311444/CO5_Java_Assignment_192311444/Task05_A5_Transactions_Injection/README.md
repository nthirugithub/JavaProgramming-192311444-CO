# A5 – Transactions and Injection (4 marks)
Transfer pseudocode: START; save original autoCommit; set autoCommit false; debit source only if balance ≥ 500; verify exactly one row; credit destination; verify exactly one row; COMMIT; on any SQL/runtime failure ROLLBACK and rethrow; restore autoCommit; END. The debit and credit form one atomic unit. Two independent auto-commit statements can leave money debited but not credited if failure occurs between them.

Unsafe concatenation can allow a crafted ID/password to alter SQL syntax (for example, a quote and tautology in the ID plus a comment terminator can neutralize the password predicate). The safe code binds both values through PreparedStatement, treating them as data, not SQL syntax. Escaping/regex validation is weaker because it is easy to miss database-specific syntax and encoding edge cases; parameter binding is the correct boundary. Both have O(1) application-side work for fixed-length values, while query execution is database-dependent.
